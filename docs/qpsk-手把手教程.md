## 开始之前：先知道自己在做什么

你要完成的事情，用一句话说：

> 自己造一堆 0 和 1 → 把它们变成 QPSK 信号 → 加噪声 → 再判回 0 和 1 → 数错了多少 → 画成曲线，并和教科书的理论公式对比。

这条链路在通信里叫**基带收发链路**，你接下来做的每一步都是它的一小段。先看一眼终点长什么样：[默认参数生成的 BER 图](../reports/qpsk/qpsk_ber.png)、[接收星座图](../reports/qpsk/qpsk_constellation.png)。

### 你的背景怎么帮到你

| 你已经会的                     | 在这里对应什么                               |
| ------------------------------ | -------------------------------------------- |
| C++ 的循环、函数、变量         | Python 里都有，只是写法更简单，不用声明类型  |

**不用手打路径**。回到 Finder（桌面那个笑脸图标），找到 `apple-mqe-interview` 文件夹。在终端里：


**应该看到**：`ls` 的输出里有 `README.md`、`pyproject.toml`、`notebooks`、`qpsk` 这些名字。看到就说明你站在了对的地方。

- `.` 是当前目录，`..` 是上一级目录
- 以 `/` 开头的是**绝对路径**（从电脑根目录数起）；不以 `/` 开头的是**相对路径**（从当前位置数起）

想往上退一级：`cd ..`。想回主目录：`cd ~`。

## 第 4 关：跟着 14 格做实验（核心）

Notebook 一共 14 格。下面按实验分组讲，你对照着做。**每格执行前先猜一下会发生什么，执行后看看猜对没有**，这样学得最快。

### 实验 A：把两个比特变成一个点（cell 1、3、4）

**先手算，再看代码。** 在纸上写这四组比特：`00`、`10`、`11`、`01`。

规则：第一比特是 0 就把 I 设为 `+1`，是 1 就设为 `-1`；第二比特同理决定 Q。幅度再乘一个 `AMPLITUDE`（约 0.707）。所以：

- `00` → `( +0.707, +0.707 )`，右上角
- `10` → `( -0.707, +0.707 )`，左上角
- `11` → `( -0.707, -0.707 )`，左下角
- `01` → `( +0.707, -0.707 )`，右下角

这四个点就是 **QPSK 星座**。两个比特决定一个符号，四个符号对应四个象限——这就是 QPSK 的"4"和"每符号 2 比特"的由来。

**C++ 对照**（cell 3 的 `map_bits`）：

| Python                            | C++ 里你熟悉的东西                                          |
| --------------------------------- | ----------------------------------------------------------- |
| `bits.reshape(-1, 2)`             | 把一维数组按每两个一组当成二维数组，`-1` 表示行数让它自己算 |
| `bit_pairs[:, 0]`                 | 取所有行的第 0 个元素，相当于循环里的 `pair[0]`             |
| `1.0 - 2.0 * b`                   | `b` 是 0 得 `+1`，是 1 得 `-1`，一个表达式代替 if-else      |
| `1 + 1j`                          | C++ 要写 `std::complex<double>(1,1)`，Python 直接 `1+1j`    |
| `np.column_stack((i_bit, q_bit))` | 把两个数组并排成两列                                        |
| `.ravel()`                        | 把二维数组拉平回一维                                        |

**执行 cell 3**。应该打印出四行坐标，和你手算的一致，最后一句是 `无噪声往返检查：4 组符号，8 个比特全部还原。`

> 这里没有 `for` 循环，是对整个数组一次性运算（叫**向量化**）。这是 NumPy 和手写 C++ 循环最大的区别，也是 Python 做数值计算快的原因。

### 实验 B：加噪声，看星座散开（cell 5、6）

**先看懂三个数**（cell 1 里定义的常量）：

- `SYMBOL_ENERGY = 1.0`：每个符号的能量，四个点都在半径 0.707 的圆上，平方和是 1
- `BIT_ENERGY = SYMBOL_ENERGY / 2 = 0.5`：**每个符号带 2 个比特，所以每比特能量是符号能量的一半**
- `EB_N0_DB = np.arange(0, 13, 1)`：信噪比从 0 到 12 dB，每个整数取一个点

**cell 6 的 `add_awgn` 在算什么**：

```python
eb_n0 = 10 ** (eb_n0_db / 10)   # dB 转倍数
n0 = BIT_ENERGY / eb_n0         # 噪声功率谱密度
sigma = np.sqrt(n0 / 2)         # 每一路的噪声标准差
```

`np.sqrt(n0 / 2)` 里的除以 2 是因为噪声分成 I、Q 两路，**每路分到一半功率**。这就是带教验收时要你能解释的那句话。

**执行 cell 6**，会看到两张并排的星座图：

- 左：`Eb/N0 = 0 dB`，噪声很大，四个点散成四团云，互相有重叠
- 右：`Eb/N0 = 8 dB`，噪声小很多，四团云收紧成四个清晰的点

用硬件直觉理解：噪声就像电路里的热噪声，信噪比越高，示波器上的点越集中。判决就是看点落在坐标轴的哪一侧，落在错了就翻错一个比特。

### 实验 C：判决、扫点、画理论曲线（cell 7、8、9、10）

- `decide_bits` 已经在实验 A 见过：`real < 0` 判第一个比特为 1，`imag < 0` 判第二个比特为 1。相当于"点落在 y 轴左边还是右边、x 轴上方还是下方"。
- `theoretical_ber`（cell 8）用 `0.5 * erfc(np.sqrt(10 ** (db/10)))` 算出教科书上的理论误码率。你不用推导它，只要知道这是**相干 Gray 映射 QPSK 在 AWGN 下的标准公式**，用来对照你的仿真对不对。
- cell 10 用 `ax.semilogy(...)` 画图：横轴是 $E_b/N_0$（dB），**纵轴是对数刻度**的 BER。

**执行 cell 8 和 cell 10**。你会看到蓝线（理论）和红点（仿真）叠在一起，红的沿着蓝的走。

### 实验 D：零错误和量级检查（cell 11、12、13）

**为什么高信噪比端没有红点？** 因为默认每点 40 万比特，在 11、12 dB 时可能**一个比特都没错**。BER = 0 在普通坐标上画不出来，在对数坐标上更是无穷小。

处理办法：图上用紫色的倒三角标出**零错误的 95% 置信上限**——意思是"真实 BER 有 95% 把握小于这个值"，大概 $7.49\times10^{-6}$。这不是作弊，这是处理"没观测到事件"的标准方法。

**cell 13 的量级检查**：它对错误数够多的点（理论期望 ≥ 30）做一次核对，确认仿真计数落在理论均值的 5 个标准差内。如果它报错，说明噪声归一化、映射或误码分母写错了——正好帮你发现 bug。

**执行 cell 13**，应该看到：`理论误码计数的量级检查通过，共检查 9 个点。`（默认参数下有 9 个点的理论错误数 ≥ 30，具体数字随你改的 `N_BITS` 而变）

### 动手题（cell 12 里列的三题）

做实验时一并完成，它们是你"真的懂了"的证据：

1. 在纸上写出 `10` 的 I/Q 坐标，以及 I 分量跨零后接收端会输出什么
2. 把 `N_BITS` 改成 `40_000`，从新内核重跑，比较高信噪比端的计数和零错误上限，然后**改回 400_000**
3. 先预测：如果每路噪声功率翻倍，仿真曲线相对理论会往哪边偏？把 `sigma` 临时乘以 `np.sqrt(2)` 验证，看图后改回原公式。用 `10 * np.log10(2)` 核对偏移（约 3 dB）

## 第 6 关：看懂你的图（作品级理解）

一张能拿去申请的图片，不是"跑出来就行"，而是你能回答别人任何一句追问。

**BER 图上有三样东西**：

1. **蓝线（Theory）**：理论公式算出来的，是衡量你对错的尺子
2. **红点（Monte Carlo）**：你自己仿真的结果；点越贴着蓝线，说明链路做得越对
3. **紫色倒三角（Zero errors: 95% upper bound）**：零错误点的置信上限，说明"没测到错误"不等于" BER 是 0"

**能被追问的点**（提前想好怎么答）：

- 两个比特怎么变成一个符号？→ 实验 A，四个象限
- 噪声功率为什么那样设？→ 实验 B，每比特能量是符号能量的一半，两路各分一半噪声
- 为什么仿真和理论能对上？→ 因为模型假设一致（理想同步、AWGN、Gray 映射、相干判决）
- 为什么高信噪比端看不到点？→ 零错误，用置信上限表示

**必须诚实说明**（这是学术底线）：这是**理想同步下的仿真实验**，没有做定时/载波同步、成形滤波、衰落和纠错编码；数据是程序生成的，不是实测。你可以在 PS 里说"我用 Python 仿真复现了 QPSK 在 AWGN 下的 BER 并与理论曲线对照"，**不要说**"我实现了完整的通信系统"。
