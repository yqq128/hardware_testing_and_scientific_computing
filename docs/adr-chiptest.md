# 华为芯片测试工程｜从 ATE 日志到良率归因

## 背景与目标

测试机吐出大量逐芯片日志。练习的目标是从日志回答三个工程问题：良率下降出现在哪些批次或站点，现有证据更支持哪种假设，哪些测试耗时值得进一步优化？

项目采用可复现的仿 STDF 文本日志。日志生成器提供独立的模拟真值，用于事后评估过杀和漏测。分析阶段用首测、复测、测试项和机台统计提出可验证的假设。

## 按顺序完成三个实验

| 阶段 | Notebook | 要交付的证据 |
| --- | --- | --- |
| 1. 解析和数据体检 | [01 流式解析](../notebooks/chiptest/01_chip_log_parsing.ipynb) | 解释逐片流式处理、单位换算和异常记录计数。生成逐芯片表和测试项表，核对丢失记录。 |
| 2. 良率和归因 | [02 良率归因](../notebooks/chiptest/02_chip_yield_attribution.ipynb) | 区分首测与最终良率。在同 lot 内对照机台和 site，用复测恢复率、参数分布与晶圆图给出假设和复核方法。 |
| 3. PAT 和测试效率 | [03 PAT 与测试效率](../notebooks/chiptest/03_chip_pat_efficiency.ipynb) | 比较静态阈值和残差 PAT，解释过杀与漏测的取舍。用模拟数据评估测试顺序，列出仍要验证的覆盖与良率风险。 |

在仓库根目录执行下面的命令，再打开左侧的三个 Notebook。

```bash
uv sync --locked
uv run python scripts/generate_chip_data.py
uv run jupyter lab notebooks/chiptest/
```

01 生成 02 和 03 的输入。02 写入 `chip_summary.json` 的前半部分，03 补全。重跑 02 后再跑一次 03，得到完整汇总。

## 验收与面试表达

- 能说明首测良率和最终良率的分子、分母与判定时点，并说清复测数据如何影响判断。
- 选一个机台异常和一个晶圆空间异常，用图、对照对象和复核步骤讲清证据链。用同批样片跨机复测等方法验证现场假设。
- 用模拟真值解释过杀、漏测及其代价。面试时说明日志格式、故障和真值来自仿真。
