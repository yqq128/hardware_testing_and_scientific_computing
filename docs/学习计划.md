# 四周学习计划｜Python 实操、芯片测试与通信面试

四周内做出三份你能当面复现和讲解的证据：一个小脚本、一个芯片良率案例、一份通信仿真实验记录。第一周从手算开始。时间按课程、申请和面试调整，每周只领一项技术任务。

## 开始前约定

- 你先填最近一个面试或材料截止、要准备的岗位或专业，以及每周能保护的两个 45 分钟。已有 offer 的回复期限用自己的通知核对。日期未知时，默认按下表走。
- 标准周做两次 45 分钟实操，加一次 20 分钟复盘，共 110 分钟。忙周保留一次 30 分钟实操和一次 10 分钟复盘，只交当前任务的最小证据。遇考试或硬截止可暂停，恢复后从原步骤继续。
- 最近的硬截止在 7 天内时，用下方冲刺安排替换当周任务。课程和申请的硬截止冲突时先锁定提交时间，再确认可用的陪练时段。
- 第一次打开仓库时，按 [README 的快速开始](../README.md#快速开始)在根目录准备 `uv` 环境。环境配置卡住，就先做第一项练习的手算，并把遇到的第一条阻塞发给带教。

## 第一项练习｜从 CSV 算出首测良率

从仓库根目录创建 `terminal-practice`，把下面八行数据和表头保存成 `terminal-practice/chip_practice.csv`。这个小表里的 ID 全局唯一，`pass_no=1` 是首测，`pass_no=2` 是复测，`P` 表示通过，`F` 表示失败。

```csv
part_id,site,pass_no,result
0001,1,1,P
0002,1,1,F
0002,1,2,P
0003,2,1,P
0004,2,1,F
0004,2,2,F
0005,2,1,P
0006,2,1,?
```

1. 用纸笔圈出 `pass_no=1` 的行。遇到 `?` 单独报作无效行，分母只计有效首测。先写出每个 site 的分子和分母。
2. 在 `terminal-practice/chip_practice.py` 用 Python 标准库读取 CSV，先打印读到的记录，再用循环和条件统计。输出两组 site 及总计，每组同时输出通过数、样本数与比率，另报无效行数。从仓库根目录运行 `uv run python terminal-practice/chip_practice.py`。卡在环境时先交手算与报错，下一次实操再补运行证据。
3. 把 `0003` 的首测从 `P` 改成 `F`，先写出预计变化，再运行核对。之后可加做复测后良率。以有有效首测的芯片为固定队列，每颗取最后一条有效记录，未复测时仍取首测。

原样本验收值为 site 1 的 **1/2**、site 2 的 **2/3**、总体首测 **3/5**，无效行 **1**，复测后 **4/5**。改动后总体首测 **2/5**，复测后 **3/5**，site 1 仍为 **1/2**。真实仓库的仿真案例以 `lot_id + wafer_id + x + y` 标识一颗物理芯片。进阶阅读时再对照 [芯片清洗代码](../chiptest/data.py)，观察记录缺失如何影响可比较的分母。

## 陪练怎么协作

- **你负责做和提问。** 约定一个沟通渠道。卡住先独立尝试约 10 分钟，把“我想完成什么、执行了哪条命令、预期和实际、最后几行报错、我已经试过什么”发到约定渠道。需求没说清时，先补一个输入输出例子或确认一个验收条件。允许带教演示、查资料或用 AI 获得提示。验收时由你本人复跑、解释并完成一个小改动。
- **带教负责给清楚目标、反馈和边界。** 开始前约定每周 20 分钟复盘和答疑窗口，建议普通问题在下一个约定工作日答复，临时面试改期则另约双方有空的时间。答疑先给一个下一步或定位思路。若机器或依赖阻塞，带教可协助定位，学员亲自重跑并记录步骤。陪练以学习证据验收，交付不接入公司业务。
- **第 2 周和第 4 周各确认一次去留。** 看三项证据：能否独立重跑、能否用结果回答一次追问、能否主动补齐一次求助所需的信息。若两周都排不开或目标变化，就重新选一个最小任务或暂停。最后由你写下“我更想继续测试分析、通信仿真还是暂缓，以及我为什么这么判断”。如需家属协助排期，先与你确认共享范围。

## 面试时怎么描述

可以用“我基于现有的模拟练习，亲手做了……，用……确认结果，下一步要验证……”开头。项目数据是模拟的，ATE 日志是简化文本，QPSK 使用理想化 AWGN 信道。真实实习、课程和陪练分别举证，技术问题按本人做过的步骤回答。参考答案里的数据、仪器和故障只有与你实际经历相符时才用于描述个人经历。
