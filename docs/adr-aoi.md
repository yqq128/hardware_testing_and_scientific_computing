## 下午：混淆矩阵和评价指标

### 1. 固定一个判断口径

假设：

> **正类 = 真实有缺陷。**

|                |   实际有缺陷 |   实际无缺陷 |
| -------------- | -----------: | -----------: |
| 模型判定有缺陷 | TP：正确检出 |     FP：误报 |
| 模型判定无缺陷 |     FN：漏检 | TN：正确放行 |

### 2. 需要掌握的指标

| 指标      | 公式                   | 回答的问题                         |
| --------- | ---------------------- | ---------------------------------- |
| Precision | `TP / (TP + FP)`       | 判为缺陷的样本，有多少是真的缺陷？ |
| Recall    | `TP / (TP + FN)`       | 真实缺陷中，有多少被检出？         |
| FPR       | `FP / (FP + TN)`       | 实际良品中，有多少被误报？         |
| 漏检率    | `FN / (TP + FN)`       | 真实缺陷中，有多少被漏掉？         |
| Accuracy  | `(TP + TN) / 全部样本` | 整体判断正确的比例                 |

**注意：**行业中“误报率”“误判率”“False Call Rate”等名称可能有不同统计口径。回答前，要先确认分母与统计单位。

### 3. 动手练习

假设经过独立参考判定：

```text
实际有缺陷：100 件
实际无缺陷：9,900 件

AOI 检出真实缺陷：95 件
AOI 漏检缺陷：5 件

AOI 将 495 件良品误报为不良
其余 9,405 件良品正确放行
```

请自己计算：

1. Recall 是多少？
2. Precision 是多少？
3. 良品误报率是多少？
4. 漏检率是多少？
5. 需要人工复判多少件？

**答案：**

- Recall：`95 / 100 = 95%`
- Precision：`95 / 590 ≈ 16.1%`
- 良品误报率：`495 / 9900 = 5%`
- 漏检率：`5 / 100 = 5%`
- 假设所有 AOI 报警件都复判：`95 + 495 = 590 件`

### 4. Python 必做练习

在 Notebook 中完成：

```python
from sklearn.metrics import (
    confusion_matrix,
    precision_score,
    recall_score,
)

# 1 表示有缺陷，0 表示无缺陷
y_true = [1] * 100 + [0] * 9900

# 有缺陷的 100 件：检出 95 件，漏检 5 件
# 无缺陷的 9900 件：误报 495 件，正确放行 9405 件
y_pred = (
    [1] * 95
    + [0] * 5
    + [1] * 495
    + [0] * 9405
)

tn, fp, fn, tp = confusion_matrix(y_true, y_pred).ravel()

print(f"TP: {tp}, FP: {fp}, FN: {fn}, TN: {tn}")
print(f"Precision: {precision_score(y_true, y_pred):.2%}")
print(f"Recall: {recall_score(y_true, y_pred):.2%}")
print(f"False positive rate: {fp / (fp + tn):.2%}")
print(f"Miss rate: {fn / (fn + tp):.2%}")
```

### 3. 简单练习代码

假设你的数据包含 `aoi_result` 和 `reference_result`，并且两者均为 `OK` / `NG`：

```python
import pandas as pd

df = pd.read_csv("data/raw/aoi_inspection.csv")

df["inspection_time"] = pd.to_datetime(
    df["inspection_time"],
    errors="coerce",
)

df["date"] = df["inspection_time"].dt.date

# 仅对有参考判定的记录计算结果
verified = df[df["reference_result"].isin(["OK", "NG"])].copy()

verified["is_false_positive"] = (
    (verified["aoi_result"] == "NG")
    & (verified["reference_result"] == "OK")
)

verified["is_actual_good"] = verified["reference_result"] == "OK"

summary = (
    verified.groupby(["date", "machine_id"])
    .agg(
        verified_count=("inspection_id", "size"),
        good_count=("is_actual_good", "sum"),
        false_positive_count=("is_false_positive", "sum"),
    )
    .reset_index()
)

# 分母为 0 时保持为 NaN，避免错误解释为 0%
summary["false_positive_rate"] = (
    summary["false_positive_count"]
    / summary["good_count"].replace(0, float("nan"))
)

print(summary.head())
```

**解释边界：**上面的结果只反映“有参考判定的样本”。如果这些样本大多来自 AOI 报警件，就不能把它当成全产线良品误报率。

### 3. 数据划分是高频重点

## 上午：测量系统基础

### 1. 重复性与再现性

| 概念                   | 主要关注                                       |
| ---------------------- | ---------------------------------------------- |
| 重复性 Repeatability   | 相同条件下，对同一对象反复测量是否一致         |
| 再现性 Reproducibility | 操作人员或其他规定条件变化后，测量结果是否一致 |

例如：同一块标准样品，设备重复测量 10 次，如果每次测出的缺陷长度差异都很大，需要先调查测量系统。

### 2. 区分两类输出

**连续数值：**

```text
划痕长度：0.52 mm
缺陷面积：0.13 mm²
```

可以考虑变量型测量系统分析，例如 Gage R&R。

**分类结果：**

```text
OK / NG
划痕 / 裂纹 / 污点
```

可以考虑属性一致性研究，例如：

- 同一设备重复判断是否一致。
- 不同操作员的判断是否一致。
- 设备与参考标准的判断是否一致。
- 在判定边界附近是否容易产生分歧。

### 3. 相关性不等于一致性

例如：

| 样品 | 参考设备 | 新设备 |
| ---- | -------: | -----: |
| A    |      1.0 |    1.5 |
| B    |      2.0 |    2.5 |
| C    |      3.0 |    3.5 |

两个设备的结果变化趋势完全一致，但新设备始终高出 `0.5`。

所以你可以回答：

> 我会同时检查相关性、测量偏差和差值分布，还要关注规格边界附近是否会导致不同的合格判定。

### 4. 稳定性与可靠性

- **稳定性**：今天、下周、不同班次和不同环境下，结果是否保持一致。
- **可靠性**：设备长期运行是否频繁故障，出现异常后能否恢复。

## 下午：模拟面试

### 第一组：AOI 与质量指标

#### 问题 1：什么是误报和漏检？

回答要点：

- 明确正类为缺陷。
- 误报：良品被判为缺陷。
- 漏检：缺陷被判为良品。
- 误报增加复判成本；漏检可能带来质量风险。

#### 问题 2：为什么准确率不适合单独评价 AOI 模型？

回答要点：

- 真实缺陷可能占比很低。
- 全部判为良品也可能获得很高的准确率。
- 应结合召回率、误报、漏检数量、缺陷类别和实际业务影响。

#### 问题 3：如何降低误报？

回答要点：

- 确认数据口径和基线。
- 按设备、班次、批次、缺陷类型分析。
- 先检查光学系统、工艺和标签。
- 再考虑阈值或模型优化。
- 保持对漏检的独立验证。
- 通过试点确认产线效果。

---

### 第二组：机器学习

#### 问题 4：你如何处理缺陷样本很少的问题？

回答要点：

- 先确认数据质量和缺陷定义。
- 按缺陷类型统计样本量。
- 考虑类别权重、合理采样和符合实际的数据增强。
- 收集边界样本和真实漏检样本。
- 使用合适的数据划分和指标。
- 样本不足时明确不确定性，不夸大结果。

#### 问题 5：什么是数据泄漏？

回答要点：

> 测试阶段使用了训练时不应该获得的信息，导致测试结果高于真实应用效果。

举例：

- 同一工件的相似图片同时出现在训练集和测试集。
- 用全量数据计算预处理参数后再划分。
- 使用生产时不可获得的信息作为模型特征。

#### 问题 6：如何选择模型阈值？

回答要点：

- 先确认质量风险约束。
- 比较不同阈值下的漏检和复判量。
- 按不同缺陷类型检查。
- 在独立验证集选阈值，再用测试集评估。
- 产线试运行后持续监控。

---

### 第三组：设备验证

#### 问题 7：什么是 GRR？

回答要点：

- GRR 用于分析测量系统的重复性和再现性。
- 测量结果有变化时，需要分清变化来自产品还是测量系统。
- 连续数值测量与 OK / NG 属性判定的验证方法需要区分。

#### 问题 8：新设备如何导入量产？

回答要点：

1. 明确检测目标和验收标准。
2. 准备覆盖真实情况的样品。
3. 验证检测能力、重复性和一致性。
4. 检查节拍、稳定性和可靠性。
5. 产线试运行。
6. 验收、追溯和持续监控。

---

### 第四组：协作与沟通

#### 问题 9：如果算法团队认为模型效果很好，但现场工程师不愿使用，你怎么办？

回答要点：

- 先了解现场顾虑，是漏检、节拍、可解释性还是操作复杂度。
- 共同确认评价标准和业务目标。
- 用现场样本和试运行数据验证。
- 记录误判案例并分析原因。
- 先小范围试点，形成反馈机制。

#### 问题 10：如果你的结论与供应商结论不一致，你怎么办？

回答要点：

- 对齐数据来源、样品、测试条件和指标定义。
- 复现双方的测试。
- 聚焦事实和差异原因。
- 与相关人员共同确认下一步验证方案。
- 记录结论和责任人。

## 2. What is the difference between a false positive and a false negative?

> A false positive means a good product is incorrectly classified as defective.
>
> A false negative means a defective product is incorrectly classified as good. In manufacturing, both matter: false positives increase review work, while false negatives may create quality risks.

---

## 3. Why is accuracy not enough?

> In manufacturing, real defects may be rare. A model can achieve high accuracy by predicting almost everything as good, but it may miss many defects.
>
> Therefore, I would also look at recall, false positives, false negatives, and performance for each defect type.

---

## 4. How would you reduce false calls?

> First, I would define the metrics and establish a baseline. Then I would analyze false calls by machine, shift, batch, and defect type.
>
> I would check image quality, equipment settings, and label consistency before changing the model. After that, I would compare possible solutions and validate them using independent data and a production trial.

---

## 5. How would you evaluate an inspection machine before production?

> I would first agree on the inspection requirements and acceptance criteria with the quality and manufacturing teams.
>
> Then I would use representative samples to evaluate detection performance, repeatability, and agreement with a reference method. I would also check stability, cycle time, and reliability in a production trial before rollout.
