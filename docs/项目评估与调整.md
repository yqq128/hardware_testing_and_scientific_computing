# 硬件测试与通信练习｜项目评估与调整

这套仓库适合用作短期陪练的素材库。对当前学员，最值得投入的是用 Python 独立完成一次数据处理，再把结果、判断依据和局限讲清楚。建议从一张能手算的芯片测试小表起步，随后复现一个 ATE 良率案例。港大通信方向有明确材料截止或面试时，优先交付一个亲手复现的 QPSK 实验。具体安排见[四周学习计划](学习计划.md)。

## 增补、删减与优化

- **增补第一项能独立完成的任务。** 三个芯片 Notebook 有完整实现和保存的输出，第一份已经要求读懂流式解析、单位和脏数据处理。先用八行 CSV 练文件路径、循环、条件、计数与报错，再进入仿 STDF 日志。把改一行数据并预测差异作为验收，避免把运行现成代码误记为独立完成。
- **从必修中删掉并行路线。** AOI 五天、芯片三个完整 Notebook 和 QPSK 六周是三套有价值的参考材料。对同时应付课程、申请和面试的学员，单周只领一个主题。已有看板、进阶统计、复判模型与工具链细节保留作参考，暂缓扩建看板或追加算法。
- **缩短从作业到面试的距离。** 每次只交一个可查文件或命令输出，外加一句结论和一句边界。现有面试稿用作提问清单，先合上笔记口述，再看原稿补漏。两段真实实习各整理一张证据卡，明确本人执行的操作和团队提供的支持。仓库练习另列来源，按实际完成程度使用“阅读”“复现”“独立实现”。
- **把协作边界写成可观察的行为。** 据带教观察，清晰示范后她能较快吸收、也愿意配合。用近期面试题启动练习，并通过独立复跑验证进展。任务目标、反馈时间和求助材料由双方提前约定，带教提供样例、提示和复盘。她自己选择要解决的问题，提交证据并说明下一步。家属已有的沟通窗口可协助对齐排期与陪练定位，具体目标、反馈与去留直接和本人确认。
- **用负荷和意愿决定是否继续。** 每周先确认课程截止、申请节点、已持 offer 的回复期限和面试日期。先观察她能否完成小任务、能否提供有效求助信息、是否愿意再试一个变体。两周后正常继续、缩小范围或暂停都可接受，实习按陪练安排，不承担公司的产出指标。

## 仓库核对与教学口径

- 原始日志与清洗 CSV 未随 Git 跟踪。首练使用计划内的手填 CSV，在环境或原始数据未就绪时仍可手算。后续进入 [README 的真实入口](../README.md#快速开始)，生成正式案例所需的模拟数据。
- 芯片解析器逐行读取并按晶圆整理，随后把多个晶圆的 DataFrame 保存在内存并合并。已同步校正文档、教学 Notebook 和面试稿的内存描述。GB 级日志可用来讨论后续怎么做分批写盘。
- 现有 L04 仿真中，T02 site 3 的首测良率约 66.38%，同 lot 其余芯片约 94.80%。复测恢复与接触电阻只能支持接触相关假设。一个更强的验证是让同批样片交换 site 和机台，用相同程序及测试条件复测，并观察异常跟着样片走还是跟着测试位置走。 [仿真汇总](../data/processed/chip_summary.json)
- QPSK 的默认样本包含高信噪比处的零误码点和偶发误码点。比较有限样本和理论时，应同时报告误码数、分母和零误码上限，避免把零次观测写成链路绝对无误。 [默认 BER 表](../reports/qpsk/qpsk_ber.csv)
