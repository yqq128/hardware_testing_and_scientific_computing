# 模型训练与实验技术全景（03_ml_experiment）

本项目在第 3 天的复判模型实验（`notebooks/aoi/03_ml_experiment.ipynb`）中，**远不止使用了逻辑回归（Logistic Regression）**。项目以“成本敏感复判”为核心业务场景，构建了**候选算法横评、朴素基线锚定、时序与工件级防泄漏、极端阈值搜索、统计置信区间以及产线漂移监控**的完整工业级机器学习闭环。

---

## 零、 工业级闭环的技术栈分工总览

该闭环并非单一库能涵盖，而是由 **`scikit-learn`（算法与预处理骨架）**、**`pandas` / `numpy`（产线数据工程与定制化业务逻辑）** 以及 **`scipy`（统计学严谨推断）** 协同构建：

| 实验环节 | 实际实现工具 / 库 | 职责定位与具体实现方式 |
| :--- | :--- | :--- |
| **1. 候选算法横评** | **`scikit-learn`** | `Pipeline` 封装 `ColumnTransformer`（独热、标准化、中位数填充），训练 `LogisticRegression` 与 `RandomForestClassifier`，用 `roc_auc_score` 和 `average_precision_score` 评测。 |
| **2. 朴素基线锚定** | **`pandas` + `scikit-learn`** | 直接提取设备原生打分 `aoi_score` 列，不训练任何模型，复用 `sklearn.metrics` 衡量无模型情况下的原生排序能力。 |
| **3. 时序与工件级防泄漏** | **`pandas`**（主实验）<br>+ **`scikit-learn`**（泄漏实证） | 主实验用 `pandas` 按产品首检日期统一划分时序与复测记录；第 4 节对照组用 `sklearn.model_selection` 的 `GroupShuffleSplit` 与 `StratifiedShuffleSplit` 实证泄漏效应。 |
| **4. 极端阈值搜索** | **自定义 Python + `numpy` / `pandas`** | 自定义编写网格扫描函数 `sweep()`，以向量化方式计算各阈值下的漏检数与放行数，按 `Recall ≥ 98%` 硬约束反查最优阈值（非 sklearn 黑盒封装）。 |
| **5. 统计置信区间** | **`scipy` (`scipy.stats`)** | **独立于 sklearn**。调用 `scipy.stats.binomtest(...).proportion_ci()` 计算小样本缺陷召回率的 Clopper-Pearson 95% 精确置信区间。 |
| **6. 产线漂移监控** | **`pandas`** | 利用 `pandas` 提取未见过的异常反光批次（L03 10-27 B081），统计均值亮度/对比度物理漂移及模型放行比例突变。 |

## 一、 对比模型与朴素基线（scikit-learn + pandas）

在验证集（Valid Set）上，代码同时构建了 3 个对比对象以评估算法增益：

| 模型/方法 | 关键参数配置 | ROC-AUC | PR-AUC | 选型结论与工程原因 |
| :--- | :--- | :---: | :---: | :--- |
| **LogisticRegression** | `max_iter=1000`, `class_weight="balanced"` | **0.955** | **0.900** | **入选最终模型**。泛化能力最强，权重直观且可解释，推理延迟极低。 |
| **RandomForestClassifier** | `n_estimators=300`, `min_samples_leaf=5`, `class_weight="balanced_subsample"` | **0.955** | **0.895** | **否决**。在小样本与不平衡数据下存在轻度过拟合，PR-AUC 略低于逻辑回归，且缺乏白盒可解释性。 |
| **AOI score only (no model)** | 无模型，直接基于设备原生打分 `aoi_score` 降序排序 | **0.939** | **0.883** | **朴素基线**。证明模型引入亮度和对比度特征后仅比原生设备打分带来 **+0.017** 的 PR-AUC 增益。 |

> **Apple MQE 核心思考**：模型的实际业务价值取决于“是否存在独立于 AOI 打分之外的有效物理信息”。若增益过小，排查光学与工艺根因的优先级远高于上线复杂算法。

## 二、 特征工程与预处理流水线（scikit-learn Pipeline）

为了杜绝在数据清洗和归一化阶段产生跨集合的信息泄漏（Data Leakage），特征工程采用 `scikit-learn` 的 `ColumnTransformer` 与 `Pipeline` 封装：

- **连续特征流水线**（`aoi_score`, `brightness`, `contrast`）：
  - `SimpleImputer(strategy="median")`：仅在训练集上统计中位数填充缺失值。
  - `StandardScaler()`：Z-score 标准化，消除量纲差异，使线性权重具有物理可比性。
- **离散分类流水线**（`defect_type`）：
  - `OneHotEncoder(handle_unknown="ignore")`：独热编码，自动忽略未见过的未知缺陷类型。
- **特征准入红线**：
  - 严格剔除目标标签（`reference_result`）。
  - 显式剔除生产中无法跨批次泛化的高基数字段（`machine_id`, `batch_id`），强制模型学习物理图像特征而非记住具体机台或批次编号。

## 三、 时序与工件级防泄漏切分（pandas 数据流工程）

在 AOI 检测场景下，被初检报警的工件通常会在产线上经历多次复测。若直接按记录随机划分，同一工件的特征近亲会同时出现在训练集和测试集，造成严重的虚假高分。

项目采用双重隔离机制：

1. **时间先后切分（Time-based Split）**：
   - 训练集（Train）：`10-01 ~ 10-20`（3,115 条报警）
   - 验证集（Valid）：`10-21 ~ 10-25`（739 条报警）
   - 测试集（Test）：`10-26 ~ 10-30`（835 条报警）
2. **工件分组（Group by `product_id`）**：
   - 使用 `pandas` 的 `groupby("product_id")["inspection_time"].transform("min")` 计算每件产品的首检日期（`product_first_date`），以首检归属统一决定该产品所有复测记录的数据集划分，彻底杜绝复测样本跨集。

## 四、 数据泄漏实证对比实验（scikit-learn Model Selection）

在第 4 节中，使用相同的 `RandomForestClassifier` 重复跑了 8 轮对比切分实验，量化数据泄漏的代价：

- **按行随机分层切分（`StratifiedShuffleSplit`，存在泄漏）**：PR-AUC 均值为 **0.872**。
- **按工件分组打乱（`GroupShuffleSplit`，严格无泄漏）**：PR-AUC 均值为 **0.854**。
- **结论**：实测证明，如果不按产品分组，模型会因“见过同一产品的复测近亲”而使 PR-AUC 虚高约 **0.017**。

## 五、 成本敏感阈值搜索（自定义 Python / numpy / pandas）

工业制造中，“漏检（False Negative）是严重质量事故与客退风险，误报（False Positive）仅增加人工复核工时”。模型绝不使用默认的 0.5 作为判定阈值：

1. **定制化网格搜索函数（`sweep()`）**：以向量化方式计算每个阈值切分下的送审数、放行数、召回率与减负比率。
2. **反向约束搜索**：设定首要质量红线为 `Recall ≥ 98%`，在独立验证集的 Precision-Recall 曲线上反向检索可满足该召回率的最大阈值，最终定出 `threshold = 0.05`。
3. **极度保守策略**：模型预测“是真实缺陷的概率 $p \ge 0.05$”（只要有 5% 的缺陷嫌疑）一律必须送人工复核；仅对 $p < 0.05$ 的极低风险报警执行自动放行。
4. **独立盲测效果（Test Set）**：
   - 测试集 835 件报警中，自动放行 278 件误报，**人工复判工作量压降 33.3%**。
   - 测试集 133 件真实缺陷中，成功保留 131 件送审，**缺陷召回率达到 98.5%**（仅漏放 2 件）。

## 六、 小样本二项比例置信区间（scipy.stats 统计推断）

测试集上真实缺陷样本量有限（仅 133 件）。为了避免把单个点估计（98.5%）当作量产放行的决定性结论，项目引入统计推断：

- 调用 `scipy.stats.binomtest` 计算 Clopper-Pearson 精确置信区间。
- 召回率的 95% 置信区间跨度为 **[94.7%, 99.8%]**。
- **工程意义**：证明在缺陷数量不多时，必须用置信区间客观表达不确定性，绝不能单凭点估计贸然上线全自动放行。

## 七、 概念与数据漂移检查（pandas 批次物理统计）

针对数据集中埋藏的异常反光批次（L03 产线 2026-10-27 B081 批次）开展应激测试：

- **输入分布漂移**：该批次均值亮度飙升（134.9 vs 常态 124.8），对比度大幅下降（18.4 vs 常态 23.4）。
- **模型行为异常**：在未见过的特征分布下，模型对误报的放行比例从正常的 36% 骤升至 **59.6%**，且该批次 3 件缺陷中漏放了 1 件。
- **质量防控防线**：生产上线必须部署统计过程控制（SPC）与放行比例监控，一旦放行比例或光学特征出现突变，系统必须立刻回退到 **100% 全量人工复判**，直至重新校准验证。

## 八、 系统级端到端风险叠加核算

跳出单个模型的微观评估，站在整条质量防线的高度进行总账核算：

$$\text{端到端缺陷拦截率} = \frac{\text{AOI 首检检出数} - \text{复判模型漏放数}}{\text{产线总真实缺陷数}} = \frac{103 - 2}{106} = 95.3\%$$

- AOI 初检首检召回率为 **97.2%**（本身漏检 3 件）。
- 复判模型对报警件的召回率为 **98.5%**（额外漏放 2 件）。
- **结论**：复判模型无法修复 AOI 设备原生的漏检，两道工序的漏检风险是乘积叠加的，端到端实际缺陷拦截率下降至 **95.3%**。
