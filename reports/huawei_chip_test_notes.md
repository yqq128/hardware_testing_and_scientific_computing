## 2. 你的硬件经历怎么接上

### 2.1 仪器类比

这是**类比**，帮助面试官看到你的经验可迁移，不是说两者等价。

| 你用过的仪器 | 芯片测试里对应的东西 | 项目里对应的测试项 |
| --- | --- | --- |
| 万用表 | DC 参数测试：接触电阻、漏电流、基准电压 | `CONT_VDD`、`CONT_IO`、`IDD_STANDBY`、`VREF` |
| 可调电源 | 电压扫描，找最低工作电压（Vmin）；shmoo 图的电压轴 | `VMIN`、`LDO_OUT` |
| 示波器 | 时序与信号完整性、电源纹波。示波器看单次波形，ATE 日志看**分布** | `SCAN_FMAX`、`VMIN` 的离散度 |
| 逻辑分析仪 | 功能向量失败时，定位是哪一拍、哪个 bit | `FUNC_PAT`、`SRAM_BIST`（失败计数） |

### 2.2 三个硬件 Bug 在数据里长什么样

芯片测试里的“硬件”主要是**测试硬件**：load board、探针卡、socket、测试机通道。
你在板子上遇到的虚焊，对应测试现场的接触不良。症状相似：间歇出现、复测会好。

| 你调试过的问题 | 数据上的指纹 | 项目里的对应线索（模拟） |
| --- | --- | --- |
| 虚焊 / 接触不良 | 只集中在一个 site；`CONT_VDD` 失败；**复测大量恢复** | L04 / T02 / site3：FPY 66.4% vs 同 lot 其余 94.8%；`CONT_VDD` 失败 27.5% vs 0%；复测恢复 55% vs 6% |
| 电源噪声 | **均值不变、离散度变大**；边缘芯片随机翻转；复测部分恢复 | L06 / T03：`VMIN` 标准差为其他测试机的 2.3 倍，均值只偏 −0.08σ；复测恢复 41% vs 8% |
| 时序不匹配 | **均值整体平移**、离散度不变；复测几乎不恢复 | T01 在 L05–L08 的 `SCAN_FMAX` 低约 0.8–1.05σ；L05、L08 复测恢复约 7% |

这三个指纹的价值在于：**“均值变了还是离散度变了”“复测能不能好”这两个问题，就能把三类硬件问题分开。**
你调试时先问“是不是每次都出现”“换一块板子还在不在”，思路和这里完全一样：

| 硬件调试 | 数据分析 |
| --- | --- |
| 先复现问题 | 看复测能不能恢复 |
| 换一块板 / 换一台仪器，隔离变量 | 同 lot 内对照其他测试机、其他 site |
| 用示波器看波形，找特征 | 看均值还是离散度变了、哪个测试项在失败 |
| 提假设（虚焊、电源纹波、时序裕量） | 写成“像……”的假设，**不下结论** |
| 修好之后再测一遍 | 修复后做前后对比 |

### 2.3 STAR 模板（把你的真实经历填进去）

> 只填你真的做过的事。数字不知道就写“没有记录”，不要编。

**案例 A：虚焊 / 接触不良**

- **S（背景）**：[ 什么板子或项目，现象是什么：偶发重启、某路信号不稳……]
- **T（任务）**：[ 你负责什么：定位原因并给出修复 ]
- **A（行动）**：[ 先怎么复现；用万用表或示波器测了哪里；怎么缩小范围；最后怎么确认是虚焊 ]
- **R（结果）**：[ 修复后现象是否消失；怎么验证；如果能量化就量化 ]
- **和这个岗位的连接**：这类问题在产线上表现为**单个 site 的接触失败、复测会好**。如果日志里看到这个指纹，我会先怀疑探针卡 / socket，而不是芯片。

**案例 B：电源噪声**

- **S**：[ ]　**T**：[ ]　**A**：[ 用示波器看了哪一路电源，纹波多大，在哪个操作下最明显，怎么处理：加电容、改布线…… ]　**R**：[ ]
- **连接**：电源噪声在数据里是**离散度变大而均值不变**，边缘芯片会随机翻转。

**案例 C：时序不匹配**

- **S**：[ ]　**T**：[ ]　**A**：[ 用逻辑分析仪看了哪些信号，建立保持时间在哪里不满足，怎么调整 ]　**R**：[ ]
- **连接**：整台测试机同一测试项的**系统性偏移**，复测不恢复，更像时序 / 校准问题，要用同一批样片在多台机器上做相关性对比。

## 3. 良率下降时的排查思路：是测试硬件，还是芯片本身

不要一上来就说“芯片有问题”或“测试机有问题”。排查顺序：

1. **固定口径**：首测良率（FPY，每颗芯片只算第一次）、复测后的最终良率、复测恢复率。复测会让良率虚高，必须分开看。
2. **按维度拆分**：lot → wafer → 测试机（station）→ site → 测试项。
3. **同 lot 内对照**：同一个 lot 里，把这台测试机 / 这个 site 和其他的比。直接跨 lot 比，会把 lot 本身的差异误当成测试机差异。
4. **看指纹**：主要失败的是哪个测试项；均值变还是离散度变；复测恢复率高还是低。
5. **提假设并写明怎么验证**：例如“像探针卡接触不良；验证：看该 site 的接触电阻分布，换针卡后对比”。
6. **修复后回归**：换了之后同一指标要回来。

项目里的实现：先用 Fisher 精确检验找“lot × 测试机 × site”里良率显著偏低的格子，同时要求**效应量**（至少低 3 个百分点），
避免样本大了以后微小差异也显著；再给每个线索算指纹（FPY、最主要的失败测试项、复测恢复率），最后由规则写出假设文字。

两个容易踩的坑：

- **整个 lot 的多个测试项同时偏移**：L07 在 4 个独立测试项上同时偏移（IDD_STANDBY +1.12σ、IDD_ACTIVE +1.20σ、SCAN_FMAX +0.87σ、VMIN −0.95σ），
  方向合起来是“更快、漏电更大、Vmin 更低”，和快角工艺一致，而且各台测试机上都有。这更像整批工艺偏移，**不是测试机问题**。
- **晶圆间差异和测试机混在一起**：这里每片晶圆固定在一台测试机上，晶圆本身的差异会混进测试机比较。
  所以测试机比较用的是**多台测试机的共识基线**（至少 3 台、取中位数），而且最终要用同一批样片（golden unit）在各台机器上做相关性验证。

## 4. 结果速查表（模拟数据）

数据规模：8 个 lot、80 片晶圆、71,907 颗芯片，日志 1,165,340 行、21.5 MB。

| 项目 | 数值 |
| --- | --- |
| 解析速度 | 0.48 秒，约 243 万行 / 秒（本机实测，纯 Python 逐行解析） |
| 首测良率 FPY / 复测后最终良率 | 92.54% / 93.20% |
| 复测恢复率（首测失败里被复测救回的比例） | 8.8% |
| 脏数据 | 306 行截断；207 个哨兵值（1E+38）；88 个 nan；946 个值需单位换算；187 颗缺 PRR；85 个重复芯片块；86 次晶圆计数与 WRR 不符 |
| 良率损失 Pareto | LEAKAGE 28.8%、SPEED 23.2%、MEMORY 18.0%、FUNCTIONAL 16.3%，前四项累计 86.3% |
| 接触不良（L04 / T02 / site3） | FPY 66.4% vs 94.8%；复测恢复 55% |
| 测试机时序偏移（T01，L05–L08） | `SCAN_FMAX` 偏低约 0.8–1.05σ；离散度不变；被标出的 L05、L08 复测恢复约 7% |
| 测试机电源噪声（L06 / T03） | `VMIN` 标准差 ×2.3；均值几乎不变 |
| 整批工艺偏移（L07） | 4 个测试项同时偏移 0.87–1.20σ（更快、漏电更大、Vmin 更低） |
| 划伤（L03 W07） | 61 颗相连失败芯片，随机预期约 7；500 次置换里没有一次更大（p ≈ 0.002，即该次数下的最小值）。L04 W05 失败也多，但只有 11 颗相连（p = 0.018），不标 |
| 径向良率（内圈到外圈） | 93.7% → 93.8% → 93.9% → 91.6% → 88.4% |
| PAT：静态 6σ | 标出 0 颗 |
| PAT：残差法 k = 4.0 | 标出 113 颗，其中 107 颗是真隐患：精度 94.7%，召回 53.5%（共 200 颗隐患） |
| PAT：残差法 k = 3.5 | 标出 157 颗，141 颗是真隐患：精度 89.8%，召回 70.5% |
| 复测的两面 | 过杀从 984 降到 568（追回 416 颗好片），同时漏测从 100 增到 157（多放过 57 颗坏片） |
| 测试时间 | `SRAM_BIST` 占 34%；调整测试顺序只能省 1.5% |
| 冗余候选 | `VREF` 与 `LDO_OUT` 几乎总是同时失败（重叠 99–100%）；去掉 `VREF` 省 2.2% 时间，**只被它抓到的失败芯片 0 颗**（这是首测数据内的口径，不含 truth） |

读表时要记住的三点：

- **过杀和漏测只在模拟数据里知道**（因为我们有 truth）。真实场景只能靠复测、可靠性试验和客退间接估计。
- **PAT 的精度 / 召回取决于我设定的“隐患”有多明显**，换一组设定数字会变。重点是方法：用残差消除正常相关性后，静态阈值看不到的隐患才露出来。
- **“冗余候选”不是“可以删除”**。VREF 与 LDO_OUT 同时失败，也可能是它们受同一个根因影响，删了一个就失去了独立检查。
  “只被它抓到的芯片是 0 颗”也只说明**这批样本里没出现**，不代表以后不会出现。真要删，需要用更大样本、可靠性数据和设计团队确认。

## 5. 概念速记

| 概念 | 一句话 |
| --- | --- |
| CP（Chip Probing，晶圆测试） | 封装前用探针卡接触晶圆上的 die，筛掉坏 die，避免浪费封装成本 |
| FT（Final Test，成品测试） | 封装后用 socket 和分选机（handler），规格更严，常见做速度分档 |
| ATE | 自动测试设备，常见平台有 Advantest V93000、Teradyne UltraFLEX / J750 等。我没有实际用过，这里只讲理解 |
| site / 多 site 并行 | 一次接触同时测多颗（本项目是 2×2 共 4 个 site），提高吞吐，但每个 site 的接触可能不同 |
| Hard bin / Soft bin | 硬 bin 决定分选机把芯片放进哪个盘；软 bin 是程序内部更细的失败分类 |
| STDF | 半导体测试数据的标准格式（二进制）。**本项目的日志是仿 STDF 命名的简化文本**，字段含义做过简化，真实解析要用专门的 STDF 库 |
| DFT（可测性设计） | 在设计里加入让测试更容易的结构：scan chain（扫描链）、BIST（内建自测，如存储器 MBIST）、JTAG（边界扫描）。核心是提高**可控制性与可观测性** |
| 覆盖率 | 一组测试能检出多少比例的假想故障（如 stuck-at、transition）。覆盖率高、测试时间短才是好方案 |
| DFM（可制造性设计） | 让设计对工艺波动更不敏感，例如留足时序和电压余量 |
| Vmin / Fmax / shmoo | 最低工作电压 / 最高工作频率；shmoo 是电压 × 频率（或时序）的二维通过 / 失败图 |
| Cpk | 过程能力指数：到最近规格限的距离除以 3σ。越大余量越大，常以 1.33 为参考线。本项目用稳健 σ（1.4826 × MAD） |
| PAT（Part Average Testing） | 通过测试规格的芯片里，再剔除参数明显偏离群体的“离群芯片”。静态 PAT 用固定倍数的 σ，动态 PAT 按 lot / 条件调整 |
| 过杀 / 漏测（overkill / escape） | 好片被判坏 / 坏片被放行。两者此消彼长，复测会降低过杀、提高漏测 |
| 相关性（correlation）/ GRR | 同一批样片在不同测试机上测，结果是否一致；用来判断测试机之间有没有系统偏差 |

## 6. 3 分钟项目介绍

以下是覆盖完整项目的示例。若你做的是复现和局部改动，就说清楚亲手重跑、修改和核对的部分。真实硬件经历只引用本人做过的内容。初学者可按[四周学习计划](../docs/学习计划.md)先准备一个案例。

> 我想用一个仿真项目说明我怎么用 Python 做测试数据分析。
>
> 我没有真实 ATE 的使用经验，所以先自己写了一个仿 STDF 的日志生成器，包含 8 个 lot、约 7 万颗芯片、117 万行日志，
> 里面故意放了几类脏数据，比如被截断的行、1E+38 的哨兵值、缺失的记录，还有同一个测试项换了单位。
>
> 第一步是**日志解析**。解析器逐行读取，按晶圆和测试轮次整理，最后合并成表。参考运行中，21.5 MB 日志的解析阶段约 0.5 秒。
> 常见日志异常在质量报告中单独计数。
>
> 第二步是**归因**。我把良率损失拆到 lot、测试机、site 和测试项，在同一个 lot 内对比不同测试机。
> 找到的线索里，有一个 site 的接触电阻失败、复测大量恢复，像探针卡接触不良，类似我之前遇到过的虚焊；
> 有一台测试机的 `VMIN` 离散度变大但均值不变，像电源噪声；还有一台测试机的 `SCAN_FMAX` 整体偏低，复测不恢复，像时序偏移。
> 我只把它们写成**假设**，并写出怎么用示波器、换针卡或同批样片去验证，因为数据只能给线索。
>
> 第三步是**参数与晶圆图分析**。我用残差法做 PAT，在静态 6σ 一颗都标不出来的情况下，找出了 113 颗里 107 颗确实是隐患的芯片；
> 但我也说明这依赖模拟数据里隐患的设定，真实场景要靠可靠性数据验证。
> 晶圆图上用置换检验确认了一处划伤，而不是看到几个红点就下结论。
>
> 第四步是**测试效率**。我发现 `SRAM_BIST` 占了 34% 的时间，调整测试顺序只能省 1.5%，真正的杠杆在耗时最长的项目。
> 我还列出了冗余候选，但明确它们**不等于可以删除**。
>
> 这个项目让我最大的体会是：**数据只能给线索，结论要回到硬件上验证。**
> 而这正是我做硬件调试时形成的习惯：先复现，再隔离变量，再提假设，最后验证。

## 7. 13 道模拟题

### Q1. CP 和 FT 有什么区别？为什么要分两次测？

- CP 在晶圆上，用探针卡；FT 在封装后，用 socket 和分选机。
- 分两次的原因是**成本**：封装有成本，CP 先筛掉坏 die，能省下这部分。FT 再把封装带来的问题（焊线、封装应力）和更严格的规格测一遍。
- 两处的测试硬件不同，所以接触问题的形态也不同（探针卡磨损 vs socket 脏污 / 针弯）。

### Q2. 什么是 DFT？scan、BIST、JTAG 各解决什么问题？

- DFT 的目的是**提高可控制性与可观测性**，让测试程序用更短时间覆盖更多故障。
- scan chain：把触发器串成链，从外部设置、读出内部状态，用于逻辑故障（ATPG 向量）。
- BIST：芯片自己产生向量并比对，典型是存储器自测（MBIST），省掉大量外部向量和引脚。
- JTAG（边界扫描）：测试引脚连接与板级互连，也常用作访问内部测试结构的通道。
- 项目里的关联：`SRAM_BIST` 占 34% 测试时间，是 DFT 方案影响测试成本的例子。
- 诚实说明：我不是 DFT 工程师，这里讲的是理解层面，没做过 ATPG 或 BIST 设计。

### Q3. 某个 lot 良率突然下降 5 个点，怎么排查？

按第 3 节的 6 步回答：**固定口径 → 拆维度 → 同 lot 对照 → 看指纹 → 提假设并写验证方法 → 修复后回归**。
举项目里的例子：L05 良率低，是 T01 一台测试机拖低的；而 L07 低，是各台测试机上多个测试项一起偏移，所以前者查测试机，后者查工艺。

### Q4. 怎么判断是测试硬件的问题，还是芯片本身的问题？

- 看**同 lot 内是否只集中在某台测试机 / 某个 site**：是，倾向测试硬件；所有测试机一起变，倾向芯片或工艺。
- 看**复测能不能恢复**：接触问题复测大量恢复（55%）；系统性偏移几乎不恢复（7%）。
- 看**均值还是离散度**：离散度变大像噪声，均值平移像校准 / 时序。
- 最终验证：同一批样片（golden unit）在多台机器上测，结果应该一致；不一致就是测试机相关性问题。

### Q5. 失败的芯片要不要复测？

要看是什么问题，**复测是双刃剑**：

- 好处：追回过杀。本项目里过杀从 984 降到 568，追回 416 颗好片。
- 代价：放过更多坏片。漏测从 100 增到 157，多放过 57 颗。
- 另外，复测会掩盖硬件问题。接触不良的 site 良率经复测看起来没那么差，所以要**同时报告首测良率和复测恢复率**，恢复率高本身就是接触问题的信号。
- 复测策略最好带条件：例如只对接触类失败复测，参数类失败不复测。

### Q6. 为什么漏电流要取对数？Cpk 怎么解读？

- 漏电流通常是**右偏的对数正态分布**，取对数后更接近正态，σ 才有意义；本项目里 `IDD_STANDBY` 在对数域分析。
- Cpk = 到最近规格限的距离 ÷ 3σ，反映余量。SCAN_FMAX 0.72、IDD_STANDBY 0.75 是余量最小的两项，如果接近量产，就是 DFM 要关注的地方。
- 要注意：上面两个数是**8 个 lot 混在一起**算的，lot 之间的差异（比如 L07 的整批偏移）会把 σ 撑大。本项目用稳健 σ（MAD）减少异常值影响，
  代码也支持按 lot 分开算（`cpk_table(..., by="lot_id")`），实际使用时两种都要看。

### Q7. 什么是 PAT？为什么用残差，不用静态 6σ？

- PAT 是在通过规格的芯片里，再把参数明显离群的剔除，因为它们可能有潜在可靠性风险。
- 静态 6σ 只看单个参数。本项目里隐患芯片的单项都没有离谱到 6σ，所以静态方法**一颗都没标出**。
- 残差法：`IDD_STANDBY` 通常和 `SCAN_FMAX`、`IDD_ACTIVE` 相关（快的芯片漏电大）。把这个正常相关性扣掉，
  剩下“漏电比同样速度的芯片高得多”的才是异常。k = 4.0 时标出 113 颗，107 颗是真隐患。
- 诚实说明：精度和召回依赖我设定的隐患幅度；真实场景要用 burn-in、HTOL 或客退数据验证 PAT 剔除的芯片确实更容易失效。

### Q8. 测试时间太长，怎么降？

按杠杆从大到小：

1. **看时间分布**：`SRAM_BIST` 占 34%。优化最耗时的项目（并行 BIST、缩短算法）比重排所有项目有效。调整测试顺序在本项目里只省 1.5%。
2. **多 site 并行**：提高吞吐，但要注意各 site 的接触一致性。
3. **删冗余测试**：先用覆盖重叠找候选（VREF / LDO_OUT），再看有多少失败芯片只被它抓到，最后和设计团队确认。**重叠高不等于可以删。**
4. **遇失败即停**：把便宜且容易失败的测试放前面（接触测试固定在最前）。工程模式下要继续测完全部项目，量产再切到遇失败即停。
5. 每一步都要用**覆盖率或漏测**约束，不能只看时间。

### Q9. 日志有几个 GB 甚至更大，你怎么处理？

- 我实测的是 21.5 MB、117 万行，0.5 秒。**这个规模不大，我不会拿它说“能处理海量数据”。**
- 当前解析器逐行读输入，但会保留已解析的各批 DataFrame，然后合并。若要控制 GB 级输入下的峰值内存，我会先试按批写出分区文件，再在磁盘上聚合。
- 到 GB / TB 级，会考虑：列式存储（如 Parquet）、按 lot 分区、并行解析，或放进数据库 / 分布式计算。这部分我没做过，只讲思路。

### Q10. 你怎么用数据说服设计团队修改 DFT 或设计？

- 先用**他们关心的口径**：例如“`SCAN_FMAX` 的 Cpk 只有 0.72，余量不够”“`SRAM_BIST` 占 34% 测试时间”，而不是只说“我发现一个异常”。
- 区分**测试问题和设计问题**：先排除接触和测试机（同 lot 对照、复测、golden unit），再把剩下的归给设计 / 工艺。
- 给出**可复现的证据和影响量**：哪个 lot、哪个测试项、多少颗、复测是否恢复、折算成良率或测试成本多少。
- 提**建议并承认不确定性**，例如“建议在下一版里评估缩短 BIST 的方案，需要你们确认覆盖率影响”。

### Q11. 你的硬件调试经历，怎么用到这个岗位？

用第 2.3 节的 STAR 回答，最后一定要加一句连接：“这类问题在测试数据里会表现为 ___，所以如果我看到 ___，我会先怀疑 ___。”

### Q12. 你没用过 ATE，入职后怎么上手？

- 诚实说没有用过，然后讲**已有的基础**：熟悉仪器测量和硬件调试；会 Python，能写解析和分析工具；理解测试流程和指标。
- 讲**学习计划**：先读 STDF 与测试流程文档；跟着前辈跑一遍 CP / FT 程序；从自己熟悉的数据分析工具入手，为团队减少重复劳动。
- 不要假装熟悉具体平台的命令或软件界面。

### Q13. 现场编程：给一份日志，统计每个 site 的良率

要点：**流式读取、按 PIR 记录 site、在 PRR 处计数、处理缺失 PRR**。

```python
from collections import defaultdict


def site_yield(path):
    total, passed = defaultdict(int), defaultdict(int)
    site = None
    with open(path) as f:
        for line in f:
            kind, *fields = line.rstrip("\n").split("|")
            if kind == "PIR":  # PIR|part|x|y|site|ts
                site = int(fields[3])
            elif kind == "PRR" and site is not None:  # PRR|part|hbin|P/F
                total[site] += 1
                passed[site] += fields[2] == "P"
                site = None
    return {s: passed[s] / total[s] for s in sorted(total)}
```

面试官可能追问：

- 这个口径把**复测**也算进去了，会虚高。要按 `(lot, wafer, x, y)` 去重，只取第一次，才是首测良率。
- 截断行、缺失 PRR 怎么办：`PIR` 之后没有 `PRR` 就会被下一个 `PIR` 覆盖，实际使用时要计数并报告。
- 想快一点：避免逐行建对象；超大文件按文件并行。

## 11. 与 Apple MQE 内容的复用关系

同一套方法，两个岗位：**先固定口径，再拆维度、对照、找指纹，最后提假设并验证。**

| Apple MQE（AOI 检测） | 华为 芯片测试 | 共同的方法 |
| --- | --- | --- |
| 误报率：同一件产品只算首检 | FPY：同一颗芯片只算首测 | 先固定统计单位，复测 / 复检不能重复计数 |
| M03 设备光源衰减（同批次 M04 正常） | 某台测试机 / 某个 site 异常（同 lot 其他正常） | 同批次内做设备对照，再现场验证 |
| 批次 B081 反光，所有设备误报上升 | L07 整批工艺偏移，各台测试机上都有 | 所有设备一起变，倾向批次 / 来料 / 工艺 |
| 误报复判：Recall 约束下选阈值 | PAT：残差阈值 k 的精度 / 召回取舍 | 阈值要同时看漏检（漏测）与误伤（过杀） |
| 全量参考判定只在模拟数据里有 | 过杀 / 漏测只在模拟数据里有 truth | 真实场景只能间接估计，要诚实说明 |
| GRR / 一致性 / 稳定性 | 测试机相关性（golden unit） | 测量系统本身要先验证可信 |
| 设备验证方案 `validation_plan.md` | 假设后的验证方法（换针卡、示波器、多机比对） | 数据给线索，现场验证给结论 |

建议的练习顺序：先把 Apple 笔记的 1–3 节讲顺，再看本笔记的第 3 节，会发现是同一个思路换了词汇。
